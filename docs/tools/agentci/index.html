agentci: detect prompt injection in AI-agent GitHub Actions in AI agents

Audits GitHub Actions workflows that run AI agents for prompt injection and excess privilege, offline.

What it detects

Audits GitHub Actions workflows that run AI agents for prompt injection and excess privilege, offline.

Agent actions (Claude Code, Codex, Gemini CLI, actions/ai-inference, home-grown claude -p / curl api.openai.com steps) are increasingly wired to issues, issue_comment and pull_request_target. That means any GitHub user can write text that lands in an LLM prompt, and that LLM often holds a write-scoped GITHUB_TOKEN, cloud secrets and a shell. This is the "prompt injection in CI" class (sometimes called *PromptPwnd*). agentci finds the AI steps in your workflows and reports how untrusted text reaches them, who can trigger them, and what they can do once hijacked.

Standard library only (it has its own small YAML-subset parser). No network.

Usage

cd tools/agentci
python3 agentci.py examples/risky              # 3 workflows, 26 findings, exit 1
python3 agentci.py examples/clean --fail-on any # 2 AI workflows, 0 findings, exit 0
python3 agentci.py                              # defaults to ./.github/workflows
python3 agentci.py .github/workflows --sarif > agentci.sarif
python3 agentci.py . --ai-action 'acme/review-bot*' --json --min-severity medium

After pip install of the kit, the same options work as agentsec agentci …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec agentci path/to/input --sarif > agentci.sarif

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: agentci
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

  • Heuristic and static. It reads YAML, not runtime behaviour. It does not know what an agent will do

with the text it is given, and a clean report does not mean the workflow is safe.

  • AI step detection uses a list of known action names and globs plus a regex for common CLIs and API

hosts. Unusual wrappers, composite/reusable workflows (uses: ./... or workflow_call) and Docker actions are not followed; add them with --ai-action.

  • Indirect injection is not traced. An agent that fetches an issue or PR body itself is still exposed

to its content; agentci only flags the trigger/gate/permission side of that (AC02, AC04, AC05). Data flowing through step outputs (steps.x.outputs.y) into prompts is not followed.

  • Gate detection is a regex over if: (author_association, actor, sender, label, ...). It cannot tell

whether a condition is actually correct.

  • YAML subset. Anchors/aliases, tags and complex keys are not supported; unusual files fail with a parse

error (exit 2) instead of being guessed at. Action input names change between versions; checks use the names documented as of 2026.

  • claude-code-action's built-in write-access check is assumed to be on; other actions are assumed to have none.
