canarytrap: detect prompt-injection resistance with canary payloads in AI agents

An offline, standard-library-only Python 3 CLI that smoke-tests AI agent pipelines and MCP tool-output consumers for indirect prompt injection and data exfiltration. It feeds a fixed corpus of canary-tagged attack payloads (as they would appear inside web pages, files, emails, JSON API results, code comments, etc.) into any command you point it at, then looks for success signals in the captured output: canary echo, attacker URL, forbidden tool names, or a planted fake secret.

What it detects

An offline, standard-library-only Python 3 CLI that smoke-tests AI agent pipelines and MCP tool-output consumers for indirect prompt injection and data exfiltration. It feeds a fixed corpus of canary-tagged attack payloads (as they would appear inside web pages, files, emails, JSON API results, code comments, etc.) into any command you point it at, then looks for success signals in the captured output: canary echo, attacker URL, forbidden tool names, or a planted fake secret.

Honesty note. canarytrap is a smoke test with a fixed heuristic corpus, not a red-team suite and not a proof of safety. A RESISTED verdict means none of the string detectors fired on this corpus — it does not mean the agent is safe. Real models are nondeterministic; use --repeat N and expect variance. Detection is string-based, so obfuscated or encoded leaks (chunked canaries, homoglyph secrets, novel domains) can be missed. The built-in payloads are illustrative, not exhaustive.

Rules

ScriptBehavior
examples/naive_agent.pyFollows injection cues; echoes canaries, URLs, secrets, tool names → COMPROMISED

Usage

# Browse the corpus
python3 canarytrap.py list
python3 canarytrap.py list --json

# Generate payload files + manifest
python3 canarytrap.py gen -o /tmp/ct-out --wrap

# Run against a command (stdin by default)
python3 canarytrap.py run -- python3 examples/naive_agent.py
python3 canarytrap.py run -- python3 examples/hardened_agent.py

# Pass input as a file argument
python3 canarytrap.py run -- python3 examples/hardened_agent.py {FILE}

# JSON report, repeat for flaky models, filter by category
python3 canarytrap.py run --json --repeat 3 --category tool_hijack -- \
  python3 my_agent.py

# Check a saved transcript against a gen manifest
python3 canarytrap.py check --manifest /tmp/ct-out/manifest.json \
  --output /tmp/agent-transcript.txt

After pip install of the kit, the same options work as agentsec canarytrap …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec canarytrap path/to/input --json > canarytrap.json
# canarytrap does not yet emit SARIF; use --json and keep --fail-on for CI.

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: canarytrap
    paths: path/to/input
    fail-on: high

--sarif is not available on this tool yet (resultguard and toolpoison are reserved as good first issues). Use --json and a --fail-on exit gate instead.

Known limits

  • Fixed corpus (~28 payloads); not a substitute for adaptive red-teaming.
  • String detectors only — encoding, chunking, or novel exfil channels evade them.
  • RESISTED ≠ safe. Use alongside human review and stronger evals.
  • Nondeterministic models: prefer --repeat N and look at rates, not a single pass.
  • Offline / local only by design; payloads use the fictional domain

attacker.example and synthetic FAKE-SECRET-* / CT-* tokens.
