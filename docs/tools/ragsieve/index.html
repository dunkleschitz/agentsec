ragsieve: detect indirect prompt injection in RAG documents in AI agents

Offline, stdlib-only Python 3 CLI that scans documents before they go into a RAG corpus or agent knowledge base. It looks for the shapes of indirect prompt injection and data exfiltration payloads: hidden HTML text, instruction-laden comments, invisible Unicode smuggling, AI-directed commands, exfiltration image URLs, fake chat-role delimiters, encoded blobs, and CSV formulas.

What it detects

Offline, stdlib-only Python 3 CLI that scans documents before they go into a RAG corpus or agent knowledge base. It looks for the shapes of indirect prompt injection and data exfiltration payloads: hidden HTML text, instruction-laden comments, invisible Unicode smuggling, AI-directed commands, exfiltration image URLs, fake chat-role delimiters, encoded blobs, and CSV formulas.

It is the document-content sibling of *toolpoison* (which scans MCP tool manifests).

Rules

RS01hidden-html-texthigh / mediumText inside elements hidden by display:none, visibility:hidden, font-size:0/<2px, opacity:0, color equal to background or transparent, off-screen left/top/text-indent:-9999px, clip:rect(0,0,0,0), scale(0), zero size with overflow hidden, hidden attribute. High if the text is instruction-like, medium otherwise. aria-hidden="true" is only flagged when the text is instruction-like
RS02comment-instructionhighHTML/Markdown comments containing instruction-like text (benign TODO comments are ignored)
RS03invisible-unicodemedium (high if ≥8 in a run)Zero-width and invisible format chars (ZWSP, WJ, invisible operators, mid-text BOM, Hangul fillers, ...). Single ZWJ/ZWNJ between non-ASCII chars (emoji, Indic, Persian) is ignored. Phrase rules also run on text with these chars removed, so ig\u200bnore previous instructions is still caught

RS05bidi-controlmedium (RLO/LRO high)Bidi embeddings, overrides, and isolates (Trojan-Source style display/logic mismatch)
RS06variation-selector-smugglinghigh / mediumRuns of variation selectors (FE00–FE0F, E0100–E01EF), decoded as bytes when they form valid UTF-8. A single VS16 after an emoji is fine
RS07ai-directed-instructionhigh"ignore/disregard previous instructions", "you are now ...", "system prompt", "as an AI assistant you must", "do not tell the user", "note to the AI", "if you are an LLM", "reveal your instructions", "from now on respond only with", jailbreak terms

Usage

python3 ragsieve.py corpus/                       # table output, exit 1 if any HIGH finding
python3 ragsieve.py corpus/ --json > report.json  # machine-readable, includes per-chunk scores
python3 ragsieve.py corpus/ --sarif > ragsieve.sarif   # SARIF 2.1.0 for code-scanning UIs
python3 ragsieve.py docs/ --min-severity medium --fail-on medium
python3 ragsieve.py docs/ --chunk-size 1000
python3 ragsieve.py docs/ --disable RS11,RS13
python3 ragsieve.py docs/ --allowlist .ragsieve-allow   # lines: "<path-glob> <RSxx|*>"
python3 ragsieve.py docs/ --strip sanitized/ --fail-on none

After pip install of the kit, the same options work as agentsec ragsieve …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec ragsieve path/to/input --sarif > ragsieve.sarif

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: ragsieve
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

Heuristic scanner, not a security boundary. A clean result does not mean something is safe. All example secrets in this repository are fake.

Full source, tests, and fixtures: tools/ragsieve/ in the repository. Install the kit with pip install git+https://github.com/dunkleschitz/agentsec.git.
