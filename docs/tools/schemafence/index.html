schemafence: detect unconstrained high-privilege tool parameters in AI agents

Offline tool-schema privilege auditor for AI agent / MCP / OpenAI / Anthropic tool definitions.

What it detects

Offline tool-schema privilege auditor for AI agent / MCP / OpenAI / Anthropic tool definitions.

Before an agent can call tools, someone decided which parameters the model may fill in. Unconstrained command, url, path, to, api_key, or sql fields turn a single prompt injection into shell, SSRF, path traversal, email exfil, credential harvest, or SQLi. schemafence reviews those *input schemas* (not live calls) and reports privilege risks with tool and parameter attribution.

Standard library only. It never connects to a network and never invokes a tool.

Rules

RuleSeverityWhat it flags
SK01criticalUnconstrained command / shell / code / script / argv parameter
SK02highUnconstrained url / uri / endpoint / webhook parameter
SK03highUnconstrained path / filepath / directory parameter
SK04highUnconstrained to / recipient / email / channel / phone parameter
SK05mediumadditionalProperties: true on a sensitive or consequential tool
SK06highModel-supplied secret/credential parameter (api_key, token, password, …)
SK07highAnnotation contradiction (readOnlyHint / destructiveHint / openWorldHint vs params or name)
SK08mediumConsequential tool (shell / pay / delete / deploy) with no required params
SK09highUnconstrained sql / query parameter on a data tool
SK10infoInventory of tools and sensitive parameter names (disable in CI with --disable SK10)

Usage

python3 schemafence.py tools.json [more.jsonl dir/ -]
  --disable RULE ...    skip rule ids (e.g. SK10 SK05)
  --json                machine-readable output
  --min-severity S      hide findings below S (default info)
  --fail-on S           exit 1 if any finding >= S (default high; any, none)
  --list-rules

After pip install of the kit, the same options work as agentsec schemafence …. Every tool also accepts --help and almost every tool accepts --json.

Example output

Flags SK01/SK03/SK05/SK07 on run_shell, SK02/SK06/SK07 on fetch_url, SK03/SK07 on write_file, SK04 on send_email, SK07/SK08 on delete_record / deploy_service, SK09 on run_sql (exit 1). examples/clean_openai.json is clean under --fail-on high (exit 0): cities/URLs/note ids are enum- or pattern-constrained. See also risky_anthropic.json, multi_server.json and generic_tools.jsonl.

python3 schemafence.py examples/risky_mcp.json --disable SK10

SARIF and CI

agentsec schemafence path/to/input --sarif > schemafence.sarif

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: schemafence
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

  • Heuristic parameter-name matching. A custom field named target that holds a

shell string may be missed; rename detection is name-based, not semantic.

  • Constraints are only what appears in the schema. Runtime allowlists enforced

only in server code are invisible here — pair with mcpsink / toolgate.

  • additionalProperties omitted (common) is not flagged; only explicit true.
  • Annotation defaults differ across MCP clients; contradictions are best-effort.
  • A clean schemafence result does not mean the tool implementation is safe.
