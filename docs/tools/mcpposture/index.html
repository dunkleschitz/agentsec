mcpposture: detect least-privilege issues in MCP client configs in AI agents

An offline, standard-library-only Python 3 CLI that audits MCP (Model Context Protocol) client configuration files for least-privilege and supply-chain risk: plaintext secrets, unpinned npx/uvx packages, privileged Docker launches, over-broad filesystem roots, shell-capable servers, plaintext or credential-bearing remote URLs, and more. It prints masked findings, a per-server risk summary and an overall A–F grade.

What it detects

An offline, standard-library-only Python 3 CLI that audits MCP (Model Context Protocol) client configuration files for least-privilege and supply-chain risk: plaintext secrets, unpinned npx/uvx packages, privileged Docker launches, over-broad filesystem roots, shell-capable servers, plaintext or credential-bearing remote URLs, and more. It prints masked findings, a per-server risk summary and an overall A–F grade.

Honesty note. mcpposture is a static config review only. It never launches servers, resolves packages or touches the network. It cannot see what a server actually does at runtime (a perfectly pinned package can still be malicious), it cannot verify token scopes or whether a key is live, and every rule is a heuristic with false positives and false negatives (e.g. MP07 "shell-capable" is name-based). A grade of A means "no smells found by these rules", not "safe".

Rules

IDSeverityNameWhat it flagsFix hint
MP01highinline-secretSecret value is stored in plaintext in the config file (env, header, or arg); config files get synced, shared, committed and read by other tools.Reference it instead: ${VAR}/${env:VAR}, VS Code ${input:id} with password:true, or an OS keychain/secret manager.
MP02highinline-bearer-tokenAuthorization header carries a literal Bearer/Basic credential.Use ${input:...}/${env:...} substitution or the client's OAuth flow instead of a pasted token.
MP03mediumunpinned-packagePackage/image is fetched at launch without an exact version (or @latest); a compromised or hijacked release runs with your privileges on next start.Pin an exact version (pkg@1.2.3, pkg==1.2.3, image@sha256:...) and review upgrades deliberately.
MP04lowauto-install-no-promptnpx -y/--yes installs whatever resolves without confirmation.Pin the version; preferably install once to a vetted location and run the local binary.
MP05highdocker-privilegedContainer launched with privileges that weaken isolation (privileged, host network/pid/ipc, added caps, host root or docker.sock mounts, unconfined seccomp/apparmor).Drop the flag; mount only the specific directories needed, read-only where possible; never mount docker.sock.
MP06highbroad-filesystem-rootFilesystem-type server is granted an over-broad root (/, ~, $HOME, a whole user profile, drive root, /etc ...), exposing SSH keys, browser profiles, cloud creds.Grant only the project directories the agent needs.
MP07mediumshell-capable-serverServer is launched through a shell or looks like a shell/terminal/exec MCP server (heuristic, by name). Such servers give the model arbitrary command execution.Prefer narrowly-scoped servers; require per-call confirmation; run in a sandbox/container with no secrets.
MP08highplaintext-remoteRemote MCP server reached over plain http:// / ws:// to a non-localhost host; traffic and tokens can be read or modified in transit.Use https:// (wss://).
MP09highcredential-in-urlRemote URL embeds credentials in userinfo or a secret-looking query parameter; URLs leak into logs, history and proxies.Move the credential to a header populated from ${input:...}/${env:...} or use OAuth.
MP10highuntrusted-exec-pathCommand or script runs from a world-writable/temp/download location that other users or processes can replace.Install the binary/script to a user-owned, non-writable-by-others location.
MP11criticalpipe-to-shellLaunch arguments download and execute remote code (curl\sh, wget\
MP12mediumbroad-scope-credentialCredential type cannot be narrowly scoped or is long-lived (GitHub classic PAT ghp_, AWS long-term AKIA key, live payment key). Actual scopes cannot be verified offline.Use fine-grained/short-lived credentials (github_pat_ fine-grained, AWS SSO/STS role, restricted keys).
MP13lowsecret-concentrationMany secret-bearing variables are handed to a single server, enlarging blast radius if it is compromised.Split responsibilities; give each server only the credential it needs.
MP14hightls-verification-disabledEnvironment disables TLS certificate verification (NODE_TLS_REJECT_UNAUTHORIZED=0, PYTHONHTTPSVERIFY=0, ...).Remove the override; add a proper CA bundle if needed (NODE_EXTRA_CA_CERTS / SSL_CERT_FILE).
MP15mediumcode-injection-envEnvironment sets loader/interpreter injection variables (LD_PRELOAD, DYLD_INSERT_LIBRARIES, NODE_OPTIONS --require, PYTHONSTARTUP...).Remove unless strictly required and the referenced code is trusted.
MP16lowunmasked-secret-inputVS Code inputs entry looks like a secret but is not declared with "password": true, so it is echoed when typed.Add "password": true to the input definition.
MP17infoduplicate-server-nameSame server name defined in multiple files; which one wins depends on the client and precedence can surprise you.Rename or remove one definition.
MP18infoduplicate-packageSame package/image launched by more than one server entry (possibly with different versions/credentials).Consolidate into a single entry.

Usage

python3 mcpposture.py ~/Library/Application\ Support/Claude/claude_desktop_config.json
python3 mcpposture.py .                      # discover configs under the project
python3 mcpposture.py .cursor/mcp.json --json
python3 mcpposture.py . --sarif > mcpposture.sarif
python3 mcpposture.py . --min-severity high  # only high/critical (and exit on them)
python3 mcpposture.py . --select MP01,MP02,MP09   # only secret rules
python3 mcpposture.py . --ignore MP07 --exit-zero
python3 mcpposture.py --list-rules

After pip install of the kit, the same options work as agentsec mcpposture …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec mcpposture path/to/input --sarif > mcpposture.sarif

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: mcpposture
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

  • Static config review only. No server is started and no package is

downloaded; what a server *does* (tools it exposes, files it reads, network calls it makes) is invisible. Pair with runtime controls, sandboxing and tool-description review (see toolpoison in this kit).

  • Token scopes cannot be verified offline. MP12 only reasons about token

*type* by prefix (classic ghp_ PATs can't be repo-scoped; AKIA keys are long-lived and might be root/IAM-user keys). A fine-grained token may still be over-privileged; a flagged one may be tightly scoped.

  • Heuristics have false positives and negatives. Secret detection relies on

key names and known token shapes; custom secret formats or oddly named keys are missed, and long non-secret values under secret-like names may be flagged. MP07 matches names like shell, terminal, exec, ssh, desktop-commander. MP06 only inspects positional args of filesystem-looking servers.

  • Pinning to an exact version reduces surprise upgrades but does not prove the

pinned release is benign; lockfiles/digests and provenance checks are out of scope.

  • Client-specific precedence (global vs. project configs, env inheritance,

envFile, keychain integrations) is not modelled.

  • Line numbers point at the server's name key, not the exact offending value.
