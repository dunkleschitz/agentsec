hitlguard: detect missing human approval on consequential tool calls in AI agents

Offline human-in-the-loop (HITL) gap detector for AI agent transcripts.

What it detects

Offline human-in-the-loop (HITL) gap detector for AI agent transcripts.

Consequential tool calls — pay, transfer, delete, deploy, force-push, send email, slack post, shell rm -rf — that fire without a nearby confirm-shaped user turn or approval-tool success are a common autonomy failure mode. hitlguard reads saved transcripts, classifies each tool call by name and argument risk, and flags those that lack confirmation inside a configurable lookback window.

Standard library only. It never runs an agent and never contacts the network.

Rules

RuleSeverityWhat it flags
HG01criticalCritical-tier tool (pay/transfer/destroy/force-push/prod deploy/…) without nearby confirmation
HG02highHigh-tier tool (send email/slack/delete/deploy/publish/shell/…) without nearby confirmation
HG03highBurst of unconfirmed consequential tools (--burst, default 3)
HG04highAssistant said it would skip asking, then took a consequential action
HG05criticalConfirm-shaped text in an assistant/tool role (spoofed approval)
HG06mediumBlanket pre-authorization ("always approve", "don't ask again") followed by consequential calls
HG07mediumApproval-tool success with no matching approval tool call in lookback
HG08infoInventory of consequential calls and confirmation status

Usage

python3 hitlguard.py transcript.json [more.jsonl dir/ -]
  --window N           events to look back for confirm/approval (default 6)
  --burst N            unconfirmed consequential calls → HG03 (default 3)
  --require GLOB ...   tool-name globs that always require confirmation
  --safe GLOB ...      tool-name globs that never need confirmation
  --disable RULE ...   skip rule ids
  --json               machine-readable output
  --min-severity S     hide findings below S (default info)
  --fail-on S          exit 1 if any finding >= S (default high; any, none)
  --list-rules

After pip install of the kit, the same options work as agentsec hitlguard …. Every tool also accepts --help and almost every tool accepts --json.

Example output

python3 hitlguard.py examples/risky_openai.json --disable HG08
python3 hitlguard.py examples/clean_confirmed.json --disable HG08
python3 hitlguard.py examples/clean_approval_tool.jsonl --json

# GitHub Actions (composite action ships with the repo)

  with:
    tools: hitlguard
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

  • Heuristic tiering from tool names and a few argument shapes. A tool named

helper that secretly wires money will not be flagged unless you --require it.

  • "Confirm-shaped" matching is English-centric and can false-positive on short

replies, or false-negative on unusual phrasing / button clicks that were never logged as text.

  • Only sees what the transcript recorded. UI approval clicks, out-of-band Slack

reactions, or unlogged gates are invisible.

  • Coding-agent write_file / read_file loops are intentionally low-noise

(medium or ignored). Use --require for paths that must always be gated.

  • A clean result does not prove a human approved the action in the real system.
