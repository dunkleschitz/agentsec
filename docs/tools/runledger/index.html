runledger: detect token and cost overruns in agent runs in AI agents

Offline, stdlib-only Python CLI for token and cost accounting of AI agent runs, computed from transcripts and usage logs you already have.

What it detects

Offline, stdlib-only Python CLI for token and cost accounting of AI agent runs, computed from transcripts and usage logs you already have.

Honesty note. runledger counts what your logs report. It cannot see your provider's bill, cannot verify billing, and does not know about discounts, batch pricing, tiers, minimums, taxes, or price changes. Every dollar figure is an estimate from a price table *you* control. The shipped prices.json is an EXAMPLE only - prices change and those numbers are not authoritative. Models missing from the table are reported as unpriced, never guessed.

Rules

This tool does not publish a numbered rules table; see the README for what it flags.

Usage

python3 runledger.py examples/                          # table report for a directory
python3 runledger.py run.jsonl --json > report.json     # machine-readable
python3 runledger.py logs/ --csv > turns.csv            # one row per turn
python3 runledger.py logs/ --csv --csv-group tool       # one row per tool
cat run.jsonl | python3 runledger.py - --top 10         # stdin
python3 runledger.py logs/ --budget 5.00                # exit 1 if estimate > $5
python3 runledger.py logs/ --prices my_prices.json      # your own price table
python3 runledger.py logs/ --no-prices                  # tokens only

After pip install of the kit, the same options work as agentsec runledger …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec runledger path/to/input --json > runledger.json
# runledger does not yet emit SARIF; use --json and keep --fail-on for CI.

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: runledger
    paths: path/to/input
    fail-on: high

--sarif is not available on this tool yet (resultguard and toolpoison are reserved as good first issues). Use --json and a --fail-on exit gate instead.
