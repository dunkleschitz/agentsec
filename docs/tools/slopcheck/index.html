slopcheck: detect hallucinated and typo-squatted package names in AI agents

Offline, stdlib-only Python 3 CLI that flags hallucinated-package / slopsquatting risk in the dependency lists and imports that AI coding assistants produce.

What it detects

Offline, stdlib-only Python 3 CLI that flags hallucinated-package / slopsquatting risk in the dependency lists and imports that AI coding assistants produce.

AI assistants sometimes invent plausible package names (langchain-utils-pro, python-openai-helper) or make typos (reqeusts). Attackers can register those names ("slopsquatting") and wait for someone to install them. slopcheck gives you a quick, offline first pass so you know which names to go verify by hand.

Rules

IDSeverityMeaning
SC01infoNot in snapshot or allowlist: unverified, check the registry yourself
SC02highNear-miss of a well-known name: Damerau-Levenshtein ≤1 (names ≤6 chars) or ≤2, separator confusion (pythondateutil), npm case confusion (React)
SC03mediumHallucination shape: popular base + generic affixes (-utils, -helper, -sdk, -api, -py, python-, -js, -pro, ...) where the combination is unknown
SC04mediumEcosystem confusion: npm-only name in Python deps (axios in requirements.txt) or vice versa
SC05lowUnpinned / loose version (pandas, >=1.0, *, latest)
SC06mediumDirect URL / VCS / git dependency bypasses the registry
SC07lowImported but not declared (only when manifests and sources of that ecosystem are scanned)
SC08lowDeclared but never imported (dev deps and common tools like pytest/black are skipped)

Usage

python3 slopcheck.py [PATHS ...]            # files or directories, default "."
  --allow FILE          allowlist, one name per line (# comments ok; repeatable)
  --known FILE          use another snapshot JSON ({"pypi": [...], "npm": [...]})
  --json | --sarif      JSON or SARIF 2.1.0 output (default: text table)
  --min-severity LEVEL  info|low|medium|high (default info)
  --fail-on LEVEL       high|medium|low|any|none (default high) -> exit 1
  --no-usage            skip SC07/SC08
  --list-rules

After pip install of the kit, the same options work as agentsec slopcheck …. Every tool also accepts --help and almost every tool accepts --json.

SARIF and CI

agentsec slopcheck path/to/input --sarif > slopcheck.sarif

# GitHub Actions (composite action ships with the repo)
- uses: dunkleschitz/agentsec@v0
  with:
    tools: slopcheck
    paths: path/to/input
    fail-on: high

SARIF 2.1.0 can be uploaded to GitHub code scanning. The composite action writes per-tool reports under agentsec-sarif/ by default.

Known limits

Heuristic scanner, not a security boundary. A clean result does not mean something is safe. All example secrets in this repository are fake.
