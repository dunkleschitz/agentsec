Why agentsec

A small, offline toolkit is not a substitute for a red team or a runtime gateway. Here is where it sits next to other open-source agent-security scanners, and when you would pick something else.

Published 9 November 2026 · Snapshot of public project docs as of that date. Other projects move quickly; treat this as a map, not a scorecard.

Most “AI security tools” do different jobs. Some probe a live model. Some lint agent source code. Some discover and scan MCP servers on your laptop. Some sit in the request path and filter prompts. agentsec does none of those. It reads files you already have — transcripts, MCP client configs, tool-definition snapshots, prompt templates, memory dumps — and emits findings without a network, a model, or a third-party package.

That is a narrow job, and it is intentionally so. The points below are differences, not rankings. Several of these projects are more mature, more widely used, or more complete in their own category than agentsec is in theirs.

When agentsec is a good fit

  • You already save agent transcripts, MCP client configs, or tools/list snapshots, and you want a CI gate on those files.
  • The scan has to run in an air-gapped job, a distroless image, or any environment where pip install of a stack of AI libraries is unwelcome. The tools are single Python files and the kit’s only runtime requirement is Python 3.10+.
  • You need a specific check that source linters and model probes do not cover well: secret flow from a tool result into a later webhook, tool-result prompt injection, MCP tool-definition drift against a lockfile, least-privilege grades of a Cursor or Claude Desktop config, or PII in a shared log.
  • You want SARIF or JSON from a composite GitHub Action, or a pre-commit hook, without standing up a model or an account.

When you should use something else

  • You need to know whether the model can be jailbroken. That is garak, promptfoo, or LLMSecTest. agentsec never talks to a model. A clean transcript scan does not mean the agent would resist a new payload tomorrow.
  • You need to break a live tool-calling loop. OATA is built for dynamic testing of excessive agency and parameter-mutation bypasses. agentsec only sees what was logged.
  • You want to discover every MCP server and skill already installed on a workstation. Snyk Agent Scan auto-discovers those layouts. agentsec will grade a config or a snapshot you hand it, and it will not start the server to see what it really exposes. If sending redacted component metadata to Snyk is acceptable in your environment, Agent Scan covers a discovery problem agentsec does not.
  • You want a deep, live, or multi-engine look at an MCP server itself (YARA rules, optional LLM review, dependency CVEs, binaries). Cisco MCP Scanner is aimed at that, including an offline mode if you cannot leave the network.
  • You want to lint the Python (or similar) that implements the agent — taint into exec, unpinned tools in code, missing HITL in source. Look at Agent Audit or owasp-agentic-scanner. agentsec’s closest source-adjacent tools (vibeaudit, mcpsink, tmplfence, schemafence) are narrower heuristic scanners, not a full taint engine.
  • You need an in-process filter in front of the model. That is LLM Guard (or a commercial gateway). agentsec is an audit tool you run on artifacts, not a runtime guardrail.

Honest limits of agentsec

  • It is experimental and AI-built. The tests are extensive against synthetic, fake fixtures. The kit has not been benchmarked against public attack corpora or every vendor’s live schema.
  • Detectors are regex, AST, and value-equality heuristics. They produce false positives and false negatives. A clean result is not a proof of safety.
  • Transcript tools only see what was logged. Unlogged tool calls, transformed secrets, and servers that show a different tools/list to another client are out of scope.
  • It does not replace code review, dependency scanning, secret scanning of the repo itself, or a red-team engagement.

Using them together

A reasonable split for a team that already ships agents:

  1. Lint agent source and MCP server code in CI (Agent Audit or owasp-agentic-scanner).
  2. Grade checked-in client configs and pin tools/list with agentsec (mcpposture, toolpin, toolpoison).
  3. On every saved run, scan the transcript with agentsec (resultguard, secretflow, piiguard, pathfence, shellfence, fetchfence).
  4. Periodically red-team the live agent with garak, promptfoo, or OATA.
  5. If you need a request-path filter, add a runtime guard such as LLM Guard.

Those layers overlap on purpose. agentsec is the offline, zero-dependency layer in the middle of that list — not the whole list.
