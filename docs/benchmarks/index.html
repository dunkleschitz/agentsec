Detection benchmark

On this 85-sample synthetic corpus, overall precision is 91.5% and recall is 84.3% (43 true positives, 4 false positives, 8 false negatives).

This is a small, author-written, synthetic corpus. It is not a red-team dataset, not drawn from production traffic, and not a claim about performance on real attacks. Heuristic scanners miss things; the misses below are listed on purpose.

How a detection is counted

A sample is counted as flagged when the assigned tool reports at least one finding with severity low, medium, high, or critical. Info-level inventory rules (for example SF12, FL10) are ignored. The script is benchmarks/run_benchmark.py; the labels live in benchmarks/manifest.json. Fixtures are original and use only fake credentials and reserved documentation values (for example the SSA’s well-known fictitious SSN is not used here; tracesweep samples use obviously synthetic key material documented in the corpus README).

Four jobs are covered:

  • Prompt injection in tool results — resultguard
  • Poisoned MCP tool descriptions — toolpoison
  • Secret leaks — tracesweep (presence) and secretflow (propagation into later tool arguments)
  • Dangerous shell commands — shellfence

Weaknesses (be skeptical of a clean result)

Several malicious samples were written as evasions: typo-obfuscation, split words, non-English instructions, encodings the tool does not decode, transformed secrets, and unusual tool or shell spellings. A miss on those is expected with a regex/heuristic scanner. Unexpected misses (easy samples the tool should have caught) are treated as bugs and filed with the detection-gap label.

False negatives

  • resultguard/malicious/09-typo-obfuscation — Typo-obfuscated override ('ignroe prevous instructons')
    evasion · Deliberate misspellings of a classic jailbreak. A regex detector may miss this (false negative).
  • resultguard/malicious/10-split-words — Instruction split with punctuation and hyphenation
    evasion · Split 'ignore previous instructions' across punctuation. Likely miss (false negative).
  • resultguard/malicious/12-rot13-instruction — ROT13-encoded override with a hint to decode
    evasion · Encoded form that resultguard does not currently decode (it does base64/hex). Expected miss.
  • toolpoison/malicious/09-soft-telemetry-exfil — Soft 'debugging' instruction to put workspace contents in telemetry_id
    evasion · No classic 'exfiltrate' wording. May be missed (false negative).
  • toolpoison/malicious/10-french-instruction — French-language hidden instruction in the description
    evasion · Non-English override. English-centric rules may miss this.
  • tracesweep/malicious/09-split-key — Key split across concatenation in the result
    evasion · sk-proj- and the body are quoted separately. Pattern detectors often miss this (false negative).
  • secretflow/malicious/06-transformed-before-forward — Secret is base64-encoded before it is forwarded
    evasion · The later argument is not the literal secret. secretflow tracks exact value reuse, so this is a likely false negative.
  • shellfence/malicious/11-ifs-obfuscated-pipe — curl|bash with unusual spacing and IFS-style splitting
    evasion · Obfuscated pipe-to-shell. May be missed (false negative).

False positives

  • resultguard/benign/05-override-font-setting — UI copy about overriding a system font (rules: TR01)
    medium · Contains 'override' and 'system' in a typography setting. Should stay clean.
  • resultguard/benign/06-normal-cdn-image — Ordinary HTML with a CDN logo image (rules: TR09)
    medium · A legitimate <img src> may still hit TR09 (auto-loading resource). Documented as a possible false positive.
  • toolpoison/benign/03-email-with-audit-bcc — Email tool whose description mentions an audit BCC (rules: TP06)
    medium · Legitimate compliance BCC. A possible false-positive risk if 'BCC' is treated as shadowing.
  • toolpoison/benign/04-notes-parameter — Optional notes parameter with a harmless description (rules: TP05)
    medium · Parameter named 'notes' may trip TP05 (smuggling-parameter) even when the description is benign. Possible false positive.

Open detection-gap issues

  • #7: resultguard misses typo, split-word, and ROT13 instruction overrides (resultguard)
  • #8: toolpoison misses soft telemetry exfil and non-English hidden instructions (toolpoison)
  • #9: tracesweep misses a provider-shaped key split across string concatenation (tracesweep)
  • #10: secretflow misses a secret that is base64-encoded before it is forwarded (secretflow)
  • #11: shellfence misses IFS/spacing-obfuscated curl piped to bash (shellfence)

Limits of this benchmark

  • Every fixture was written for this repository. A detector can look strong here and still fail on a real transcript format or a novel payload.
  • The corpus is small (n=85). Percentages will move when a single sample is added or re-labeled.
  • Labels are a judgment call. A “benign” page that includes a tracking <img> is clean from an operator’s point of view and still a legitimate TR09 hit.
  • Info-level inventory findings are excluded. If we counted them, shellfence and secretflow would “detect” almost every transcript they parse.
  • All secrets are fake. tracesweep also suppresses documentation placeholders (the word example, your_api_key, and similar), which is why those values are not used as the malicious keys in this set.

python3 benchmarks/run_benchmark.py --write-pages
